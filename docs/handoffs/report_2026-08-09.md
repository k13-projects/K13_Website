## The verdict

Six of the seven lanes independently returned **NEEDS-REVIEW**. QA's lone PASS is real but scoped.

The site is **live, correctly served and clean on security and privacy fundamentals** — verified
against production. No secrets, no cookies, no real injection path, and nothing leaves the browser
except through the visitor's own mail client. The problems are concentrated in one component and in
a pile of things that were never set up.

## How the QA/compliance conflict resolves

This is the most useful thing the run produced, so it gets stated plainly rather than averaged.

- **Olga (QA) tested the contact stepper's mouse/touch happy path** — step 1 → 2, in order — and
  found nothing wrong. That finding is correct for what it covered.
- **Compliance ran a live Chromium keyboard tab-order recording** and found that
  `.screen-s{opacity:0;pointer-events:none}` and `.step-back{opacity:0}` do **not** remove elements
  from the tab order (only `visibility:hidden`, `inert`, `display:none` or `tabindex="-1"` do). A
  keyboard user tabs straight from step 1 to `#sendIt` and fires it with an empty `data` object.
- **Engineering reached the same component from a code read**: the "Your email is ready"
  confirmation at `index.html:816-825` fires unconditionally, 700ms before `mailto:` even opens,
  with no way to detect failure. That is true for any visitor with no registered mail client —
  keyboard or not.

Two lanes, two different methods, converging on one component is high-confidence, not noise.
**The compliance + engineering finding stands. The honest overall status is not PASS.**

## Fix first

1. **Fix the contact stepper.** It is the site's only lead-capture path and it can silently lie
   about success. Make inactive steps genuinely hidden and guard `#sendIt` against empty data —
   one change that also closes 8 of the site's WCAG Level-A tab-stop failures.
2. **Decide the brand canon.** README + `brand/logo` + `brand/print` (Space Grotesk, `#FF4F00`)
   versus the shipped `beta_v7 "THE DRAFTING TABLE"` system (Fraunces/Inter/JetBrains Mono,
   `#CB4D14`). Found independently by the design and compliance lanes. Costs nothing but a
   decision, and blocks any DNA/styleguide work until it's made.
3. **Decide `pricing/tiger/index.html`'s fate.** Confirmed **not leaked** — live 404, never pushed
   to `origin/main` — but it is finished, client-confidential work with **zero git backup** sitting
   inside K13's own shopfront repo.

## Broken vs. merely absent

**Broken** — the stepper bug · 4 WCAG Level-A failures · 13 computed contrast failures (worst: the
9px orange caption at **1.22:1** over the portrait).

**Absent, not broken** — `CLAUDE.md` / `SCOPE.md` · the DNA styleguide · security headers and CSP ·
branch protection on `main` · `scripts/` never committed · 6 of 8 P5 items (OG meta, sitemap,
robots.txt, dark-mode favicon, custom 404, canonical link).

The distinction matters: the first list is the site misbehaving in front of visitors, the second is
work that was never started. Only the first costs credibility today.

## Standing tension

The site markets **"WCAG · 508"** as a paid capability while failing four Level A criteria of its
own. That is the finding most likely to cost K13 a client conversation, and it is cheap to fix.
