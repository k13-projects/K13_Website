## 1. Skip link — fixed, confirmed live

Fresh page load, `Tab` (first press) → lands on `.skip-link` (`Skip to main content`). `Enter` →
`document.activeElement` is `{tag: 'MAIN', id: 'main'}` immediately. Next `Tab` → lands on the
hero "Start a project" button, and `main#main.contains(activeElement)` is `true`. This is the exact
sequence that was broken last time (it previously landed back on `.brand` in the nav). **The
regression is closed.**

## 2. Nothing focusable behind the `.sent` panel — confirmed clean

Walked the stepper for real (click `.opt` → fill `#sName` → `#nameNext` → `#emailSkip` → fill
`#sWhy` → click `#sendIt`), confirmed `#sent.on` is true, then traced 8 Tab presses from that
point. First stop: the footer `projects.k13@gmail.com` link — i.e. the tab order jumps straight
from wherever it last was to the next focusable element *after* the whole contact section, which is
correct and expected (matches the "last focusable stop is the footer link" behavior from the
08-10 baseline trace). The remaining stops wrap to `<body>` then back to the top of the document
(skip link → brand → nav links → hero CTA) — ordinary end-of-document wraparound. **None of the
previously-leaking elements (`.sc` chips, `#sWhy`, `#sendIt`, `#stepBack`) appear anywhere in the
trace.** Confirmed programmatically: `stepBody.inert === true` and `sent.inert === false`
immediately after send.

## 3. `#sendIt` still cannot fire with empty or partial data

Three adversarial attempts, all on a fresh page load (stepper at step 0/1, `data` empty):
- Forced `document.getElementById('sendIt').click()` → `#sent.on` before: `false`, after: `false`.
- Dispatched a raw bubbling `MouseEvent('click', ...)` directly at `#sendIt` → `#sent.on` stayed
  `false`.
- Partial data: clicked one `.opt` (sets `data.type` only, `data.name` still empty), then forced
  `#sendIt.click()` → `#sent.on` stayed `false`, and the stepper was redirected to the name step
  (`data-s="1"`), matching the `!data.type || !data.name` guard.

All three blocked. The legitimate full flow (used in test 2 above) succeeded normally, so the
guard isn't over-broad either.

## 4. Success copy — still honest

Review it in your mail app, then hit send."` — process language, not a false "sent" claim.

## 5. `#feedToggle` — reachable, outside `aria-hidden`, genuinely pauses

- DOM check: walked every ancestor of `#feedToggle` looking for `aria-hidden="true"` — none found
  (`insideAriaHidden: false`). It now lives as a sibling of the `aria-hidden` `<aside>`, not a
  descendant.
- Focusable: `.focus()` on it made it `document.activeElement`. Target size measured 63×24px.
- **Functional pause, re-verified with the correct selector this run** (first pass mistakenly read
  the static "Currently" label instead of the rotating `#feed` text and produced a false negative —
  caught and re-run before trusting it): clicked `#feedToggle`, held `#feed.textContent` unchanged
  across 4.2s (> the 3.8s rotation interval) — confirmed paused. Clicked again to resume, text
  changed within 4.5s — confirmed it actually restarts, not just a visual toggle.
