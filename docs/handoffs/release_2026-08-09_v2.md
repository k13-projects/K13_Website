## What I built

**`vercel.json`** — the security-headers Medium finding from `security_2026-08-09.md` (finding
#1). Sets `Content-Security-Policy`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`,
`Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (locks down camera,
mic, geolocation, payment, usb), and an explicit `Strict-Transport-Security` (Vercel already
sends its own HSTS by default, but the audit flagged it as unverified/not-repo-owned — now it's
in the repo, not just hoped-for platform default).

**The CSP, exactly as shipped:**
```
default-src 'self';
script-src 'self' 'unsafe-inline' https://cdn.jsdelivr.net;
style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
font-src 'self' https://fonts.gstatic.com;
img-src 'self' data:;
connect-src 'self';
frame-ancestors 'none';
base-uri 'self';
form-action 'self';
object-src 'none';
upgrade-insecure-requests
```

**How the allowlist was derived, not guessed:** loaded `index.html` in headless Chromium via
Playwright and captured every network response. The real external origins are exactly
`fonts.googleapis.com` (the Google Fonts stylesheet), `fonts.gstatic.com` (the actual `.woff2`
font files), and `cdn.jsdelivr.net` (the pinned Lenis script) — matching what the security audit
predicted, confirmed rather than assumed. No other third-party origin is requested anywhere:
no analytics, no fetch/XHR, no iframes. All 10 `target="_blank"` portfolio links are top-level
navigations, not fetched resources, so they need nothing in the allowlist.

**On `unsafe-inline` — the explicit trade-off, not a quiet loosening:** `index.html` has one
big inline `<script>` block (all the interaction logic — Lenis wiring, reveal-on-scroll, the
contact stepper) and eight inline `style="…"` attributes, plus a full inline `<style>` block. I
first tried the strict version: hash-pinning the exact inline script with
`'sha256-aafoxOjbPSrRJzuO4AvIGnLwhTE6Ysu2QxP5hhpkvYc='` in `script-src` instead of
`'unsafe-inline'`. It worked — zero violations, proved the same way as below. I backed off it
anyway, for one reason: **Natalia is editing `index.html` concurrently right now**, and a
byte-for-byte hash breaks the instant she touches anything inside that `<script>` tag. That
failure mode is silent (CSP just drops the script; nothing errors loudly) and it's serious — that
one script is what adds the `.in` class that reveals almost every section (`.rv` starts at
`opacity:0`), so a stale hash doesn't just lose the contact stepper, it makes most of the page
invisible. Nobody debugging "the site went blank" would think to check `vercel.json`. Given the
security audit's own read on this app — the one `innerHTML` sink (finding #3) is fed only by the
visitor's own name/email input, self-XSS only, no attacker-controlled data ever reaches it — the
marginal security gain from hash-pinning script-src doesn't justify a coupling that can silently
break the site on someone else's next commit. Same logic for `style-src 'unsafe-inline'`: eight
inline `style` attributes scattered through the markup would need per-attribute
`'unsafe-hashes'` entries (inconsistent Safari support) to avoid it, for a directive whose worst
case is CSS-based, not script-based, injection. **Recommended real fix, for later:** once the
brand-canon decision lands and `index.html` stabilizes, extract the inline `<script>` to a
same-origin `/assets/site.js` — that removes the need for `script-src 'unsafe-inline'` entirely
with no fragility, because `'self'` doesn't care what the file's bytes are.

**Proof it doesn't break the site:** served the exact repo tree locally with a small Python
`http.server` subclass that sets these exact headers (script left in
`/private/tmp/.../scratchpad/csp_test_server.py` for the record, not part of the repo), then
drove it with headless Chromium via Playwright — console listener, response listener, three
repeat runs. Result: **zero CSP violations on every run**, all 8 resources returned 200 (fonts,
the Lenis script, `assets/kazim.jpg`), `window.Lenis` loaded as a function, `document.fonts`
populated with Fraunces/Inter/JetBrains Mono, and a full-page screenshot after forcing every
`.rv` reveal confirms the whole page renders correctly — hero, work index, capabilities, the
portrait, the contact stepper. (One run hit a transient 404 fetching a Google-served font URL,
repeated three more times clean — that was Google's CDN, not the CSP; `fonts.gstatic.com` is
allowlisted and nothing was blocked.) Also verified `404.html` renders clean under the same
headers with its own font requests.

**`robots.txt`** — `Allow: /`, `Disallow: /pricing/` and `/pricing/tiger/` explicitly (the
client-confidential Tiger Hospitality page — it 404s live today but the rule belongs here
regardless of deploy state), points to the sitemap.

**`sitemap.xml`** — real production origin `https://k13projects.com/` (confirmed live,
`curl -I` → `HTTP/2 200`, `server: Vercel`, matches `README.md`'s stated domain). Only the
homepage — this is genuinely a one-page site; `pricing/tiger/` is excluded on purpose, nothing
else exists to list.

**`404.html`** — read the full 831-line `index.html` to match what actually ships today: the
`beta_v7 "THE DRAFTING TABLE"` system (Fraunces display serif, Inter body, JetBrains Mono labels,
navy `#141D35`, rust `#CB4D14`, the glass-wash background texture), not the superseded
Space Grotesk/`#FF4F00` system documented in `README.md` (that mismatch is Kazim's open decision
per the compliance/design lanes yesterday — I did not resolve it, I matched the live page).
Self-contained, no dependency on `index.html`'s CSS or JS, motion gated behind
`prefers-reduced-motion` per house rule, `meta robots noindex` on the page itself, links home and
to `projects.k13@gmail.com`. Confirmed via WebSearch of Vercel's own docs: for a static/no-build
deployment, a root `404.html` is served automatically for any unmatched route — no `vercel.json`
wiring needed, so none was added (adding an unnecessary route/rewrite would be its own way to
break the "don't touch what works" rule).

not worth chasing mid-flight. Worth a process note to Robert: two agents editing the same physical

isolation for concurrent agent passes would remove the collision risk entirely.
